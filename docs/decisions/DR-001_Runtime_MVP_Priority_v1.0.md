# Decision Record DR-001

**Title:** Runtime MVP Becomes the Top Priority
**Version:** 1.0
**Date:** 29 July 2026
**Status:** Approved by Founder
**Decision source:** Founder instruction in the canonical strategic workspace: approve the MVP plan and begin execution ("LFG")

## Context

AI-EOS has established a broad governance blueprint, a proposed v3 AI Collaboration Framework, and a proposed long-term Runtime vision. The active EC-001 charter remains incomplete, while no executable Runtime exists to validate the central operating model.

Completing the entire envisioned 80–150 page governance system before producing working software would delay the first practical learning loop.

## Decision

The highest priority is now a narrow, local-first AI-EOS Runtime MVP.

The MVP must prove that AI-EOS can accept an approved Engineering Charter and execute a governed Feature Development flow through role-based AI stages, persisted artifacts, explicit Founder approval gates, verification, and knowledge capture.

The MVP does not waive Documentation-First. Documentation will be reduced to the minimum coherent foundation required to build and verify the MVP safely.

## Consequences

1. EC-001 is narrowed to an MVP governance baseline; its broader deliverables move to the post-MVP backlog.
2. EC-002 must receive Strategic AI review before its concepts are used as the MVP architecture baseline.
3. The Runtime MVP receives its own proposed Engineering Charter.
4. Product OS, cloud, web UI, marketplace, team collaboration, and advanced provider selection are deferred.
5. There remains one active execution track. “Parallel track” language is retired for active work.
6. Commit, push, merge, deploy, and publication still require separate Founder authorization.

## Guardrails

- Founder authority and explicit approval gates remain non-negotiable.
- Runtime coordination remains deterministic around AI calls.
- AI providers remain behind a replaceable interface.
- Every stage input, output, transition, approval, and failure is persisted.
- Runtime behavior must be traceable to an approved specification.
- No Runtime implementation begins until the MVP charter and architecture pass the Founder approval gate.
