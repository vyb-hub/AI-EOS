# EC-001 MVP Amendment

**Version:** 1.0
**Date:** 29 July 2026
**Status:** MVP governance slice complete
**Applies to:** `EC-001_Bootstrap_EOS_v1.0.md`
**Authority:** DR-001

## Purpose

This amendment narrows EC-001 to the minimum governance foundation required for a safe Runtime MVP. It does not discard the original deliverables; it separates immediate prerequisites from post-MVP governance expansion.

## Revised Objective

Establish the smallest coherent governance baseline needed to charter, implement, verify, and learn from the AI-EOS Runtime MVP without weakening Founder authority, documentation-first development, traceability, or source-control controls.

## Required Before Runtime Implementation

1. Founder priority decision record.
2. MVP roadmap.
3. Strategic AI review of EC-002.
4. Runtime MVP Engineering Charter.
5. Runtime MVP architecture specification.
6. Minimum decision-record convention.
7. Explicit approval, artifact, and source-control rules.
8. A documentation index identifying canonical, proposed, informational, and deferred artifacts.

## Deferred Until After MVP Validation

- Full standalone Constitution
- Expanded Engineering Philosophy
- Comprehensive Documentation Standard
- Full ADR framework
- Full Knowledge Management specification
- Comprehensive versioning standard
- Complete template library
- Founder Journal
- Engineering Journal
- Full release-management framework
- Target 80–150 page governance corpus

These remain valid EC-001 backlog items. Deferral is sequencing, not cancellation.

## Completion Criteria for the MVP Slice

The EC-001 MVP slice is complete when:

- All required documents above exist and are internally consistent.
- EC-002 has a recorded Strategic AI disposition recommendation.
- The Runtime MVP charter explicitly preserves P-01 through P-07.
- The Runtime MVP architecture defines deterministic approval and persistence behavior.
- The Founder approves the Runtime MVP charter and architecture.

Founder approval of the Runtime MVP charter will simultaneously close this MVP slice and activate the Runtime MVP charter. Broader EC-001 work will resume from the post-MVP backlog.

The MVP slice was completed through the approved EC-003 documentation,
architecture, implementation, verification, and closure record. Broader EC-001
deliverables remain deferred backlog and are not represented as complete.

## Unchanged Constraints

- Documentation remains an input to implementation.
- Founder Knowledge may not be invented by AI.
- Every meaningful decision leaves a trace.
- Source-control and deployment actions remain separately authorized.
- Only one active execution track is permitted.
